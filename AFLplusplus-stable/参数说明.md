# AFL++ 对比脚本参数说明

## 1. target_binary（目标二进制文件）

### 是什么？
`target_binary` **必须是编译好的二进制可执行文件**，这是 AFL++ 要进行模糊测试的目标程序。

### 为什么必须是二进制文件？
- AFL++ 需要**运行**这个程序来进行模糊测试
- 它会不断生成测试输入，然后运行这个程序
- 只有编译好的可执行文件才能被直接运行

### 如何准备？

#### 方法 1: 使用内置测试程序
```bash
# 1. 编译源代码为二进制文件
./afl-cc -o test-instr test-instr.c

# 2. 现在 test-instr 就是二进制文件了
./test-instr  # 可以直接运行

# 3. 使用它进行对比测试
./utils/compare_lattice_mab.sh -t ./test-instr -i ./seeds -T 600 -n 3
```

#### 方法 2: 编译你自己的程序
```bash
# 假设你有一个 C 程序 my_program.c
./afl-cc -o my_program my_program.c

# 使用它进行对比测试
./utils/compare_lattice_mab.sh -t ./my_program -i ./seeds -T 600 -n 3
```

### 检查是否是二进制文件
```bash
# 检查文件类型
file test-instr
# 应该显示类似: test-instr: Mach-O 64-bit executable x86_64 (macOS)
# 或者: test-instr: ELF 64-bit LSB executable (Linux)

# 检查是否可执行
ls -l test-instr
# 应该显示有执行权限: -rwxr-xr-x
```

### 常见错误
❌ **错误**: 使用源代码文件
```bash
# 这样是错误的！
./utils/compare_lattice_mab.sh -t test-instr.c -i ./seeds  # ❌ .c 文件不能运行
```

✅ **正确**: 使用编译后的二进制文件
```bash
# 先编译
./afl-cc -o test-instr test-instr.c
# 再使用
./utils/compare_lattice_mab.sh -t ./test-instr -i ./seeds  # ✅ 二进制文件
```

## 2. input_dir（输入种子目录）

### 是什么？
`input_dir` 是一个**目录**，里面包含**初始的测试用例文件**（也叫"种子文件"）。

### 为什么需要种子文件？
- AFL++ 需要**初始输入**来开始模糊测试
- 它会基于这些种子文件进行变异，生成新的测试用例
- 种子文件的质量会影响模糊测试的效果

### 如何准备？

#### 方法 1: 创建简单的种子文件
```bash
# 1. 创建种子目录
mkdir -p seeds

# 2. 创建一些初始测试文件
echo "0" > seeds/seed1.txt
echo "1" > seeds/seed2.txt
echo "hello" > seeds/seed3.txt

# 3. 查看目录内容
ls seeds/
# 应该显示: seed1.txt  seed2.txt  seed3.txt

# 4. 使用它进行对比测试
./utils/compare_lattice_mab.sh -t ./test-instr -i ./seeds -T 600 -n 3
```

#### 方法 2: 使用现有的测试用例
```bash
# AFL++ 自带了一些测试用例
ls testcases/
# 可以看到很多示例文件

# 可以直接使用
./utils/compare_lattice_mab.sh -t ./test-instr -i ./testcases -T 600 -n 3
```

### 种子文件的要求
- ✅ 必须是**目录**，不能是单个文件
- ✅ 目录里可以有一个或多个文件
- ✅ 文件可以是任何内容（文本、二进制等）
- ✅ 文件大小建议不要太大（通常几 KB 到几 MB）

### 目录结构示例
```
seeds/
├── seed1.txt      # 文本文件
├── seed2.txt      # 文本文件
└── seed3.bin      # 二进制文件（也可以）
```

### 检查目录
```bash
# 检查目录是否存在
ls -la seeds/
# 应该显示目录中的文件

# 检查目录是否为空
ls seeds/ | wc -l
# 应该显示文件数量（至少要有 1 个文件）
```

### 常见错误
❌ **错误 1**: 使用单个文件而不是目录
```bash
# 这样是错误的！
./utils/compare_lattice_mab.sh -t ./test-instr -i seed1.txt  # ❌ 这是文件，不是目录
```

✅ **正确**: 使用目录
```bash
# 先创建目录并放入文件
mkdir -p seeds
echo "0" > seeds/seed1.txt
# 再使用目录
./utils/compare_lattice_mab.sh -t ./test-instr -i ./seeds  # ✅ 这是目录
```

❌ **错误 2**: 使用空目录
```bash
# 这样也是错误的！
mkdir -p empty_seeds  # 空目录
./utils/compare_lattice_mab.sh -t ./test-instr -i ./empty_seeds  # ❌ 目录为空
```

✅ **正确**: 确保目录中有文件
```bash
mkdir -p seeds
echo "0" > seeds/seed1.txt  # 至少有一个文件
./utils/compare_lattice_mab.sh -t ./test-instr -i ./seeds  # ✅ 目录有文件
```

## 完整示例

```bash
cd "/Users/ketangchen/Library/Mobile Documents/com~apple~CloudDocs/Documents/000_20250825dev/laboratory_library/AFLplusplus-stable"

# 编译测试程序（生成二进制文件）

file test-instr
# 输出: test-instr: Mach-O 64-bit executable x86_64
```

### 步骤 2: 准备种子目录
```bash
# 创建种子目录
mkdir -p seeds

# 验证目录
ls seeds/
# 输出: seed1.txt  seed2.txt  seed3.txt
```

### 步骤 3: 运行对比测试
```bash
# 使用二进制文件和种子目录
./utils/compare_lattice_mab.sh \
    -t ./test-instr \      # 二进制文件
    -i ./seeds \           # 种子目录
    -T 600 \               # 测试时间 600 秒
    -n 3                   # 每个配置运行 3 次
```

## 总结

| 参数 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `-t, --target` | **二进制可执行文件** | 要进行模糊测试的目标程序 | `./test-instr` |
| `-i, --input` | **目录** | 包含初始测试用例的目录 | `./seeds` |

### 关键点
1. **target_binary** = 编译好的可执行文件（.c 文件需要先编译）
2. **input_dir** = 包含种子文件的目录（不是单个文件）

### 快速检查清单
- [ ] 二进制文件已编译（使用 `./afl-cc`）
- [ ] 二进制文件可执行（`chmod +x` 或已自动设置）
- [ ] 种子目录已创建（`mkdir -p seeds`）
- [ ] 种子目录中有文件（至少 1 个文件）
- [ ] 路径正确（使用相对路径 `./` 或绝对路径）
